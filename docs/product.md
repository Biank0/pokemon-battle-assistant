# 产品需求草案

## 目标用户

- 想学习宝可梦对战的新手玩家
- 想优化配队和操作决策的中级玩家
- 需要赛后复盘、构筑验证的对战玩家

## 用户输入

### 配队模式

- 想使用的核心宝可梦
- 对战规则：单打 / 双打、禁用规则、世代环境等
- 偏好的战术：攻队、平衡队、受队、空间、天气、顺风等
- 已有队伍配置

### 对战模式

- 己方队伍和剩余资源
- 对方队伍和已暴露信息
- 当前在场宝可梦
- HP、异常状态、天气、场地、钉子、能力变化等
- 当前回合可选行动

### 复盘模式

- 对战日志 / replay 链接 / 手动描述
- 用户希望重点分析的问题

## 主要输出

- 推荐操作
- 候选操作排序
- 风险收益分析
- 对方可能行动预测
- 后续回合分支
- 配队弱点和调整建议
- 复盘结论

## 设计原则

1. **解释优先**：不只告诉用户怎么做，还要告诉为什么。
2. **不伪装确定性**：对不确定信息要标注假设与置信度。
3. **多方案比较**：避免只输出单一答案，至少给稳定解和激进解。
4. **面向学习**：建议要能帮助用户理解对战逻辑。
5. **可迭代**：从简化规则开始，逐步补全真实对战细节。
