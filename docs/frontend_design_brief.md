# 前端设计简报（供设计 Agent 出方案）

> 目的：为「宝可梦对战助手」Web 控制台做一轮**视觉与体验升级**。本文档是现有前端的功能全量清单与技术约束，请基于此输出设计方案（交付物要求见第 6 节）。

## 1. 产品背景（30 秒了解）

LLM 驱动的宝可梦对战全流程工具，本地部署的 Web 控制台，桌面浏览器为主（1280~1920 宽），核心使用场景：

1. 用户输入一句话需求 → **AI 建队**（约 20 秒，日志实时滚动）
2. 选两支队伍 → **对战实验室**自动跑量（Showdown 引擎真实对战，3~50 轮，进度实时刷新）
3. 一键 **AI 复盘分析**（约 20 秒）→ 结构化报告（评分/阵容表现/威胁/改进建议）

重要场景备注：本项目会用于**演示/面试展示**，第一眼专业感与数据可视化冲击力优先级高。

## 2. 技术约束（必读，方案必须在此范围内）

- **技术栈**：Vue3（CDN 全局构建）+ Element Plus + ECharts，全部 vendor 本地化
- **无构建步骤**：没有 npm/webpack/vite，不能引入需要编译的方案（Tailwind/SCSS/Less 均不可）；纯 CSS 或 CSS 变量可行
- **样式现状**：单个 `app.css`（约 300 行）+ Element Plus 默认主题；可通过 CSS 变量覆盖与深度选择器（`:deep()`/全局类）定制
- **不更换组件库**，不改变信息架构（路由 9 页固定）；界面语言中文
- **图标**：目前无图标库，可选方案——本地 SVG、Unicode 符号，或建议引入免编译的图标方案
- 字体环境：Segoe UI / 微软雅黑（可建议 Web 安全字体栈或本地字体文件）

## 3. 页面全量清单

### 3.0 全局框架
左侧固定导航 216px（logo 区 + 6 个菜单：首页/AI建队/队伍库/对战实验室/分析报告/设置 + 底部标语），右侧内容区白底浅灰背景、24px 内边距、纵向滚动。

### 3.1 首页（HomeView）★ 演示入口
- 3 张并排入口卡（AI 建队 / 队伍库 / 对战实验室），每张：标题 + 一句话描述 + 跳转按钮，队伍卡带实时数量
- 现状问题：信息密度低，无任何数据展示，「数据产品感」弱

### 3.2 AI 建队（GenerateView）★ 演示主线 1
- 上：表单卡片——建队需求 textarea（200 字）、赛制单选（BSS/OU/VGC 三项，VGC 带注记）、提交按钮
- 下：任务卡片——状态标签（进行中/完成/失败）+ **等宽字体日志流**（实时追加，如「planner 规划完成」）+ 完成态（队伍名大字 + 战术思路 + 校验轮次/token 用量 + 查看详情按钮）
- 现状问题：日志流视觉单调，完成态缺乏「成果揭晓」的仪式感

### 3.3 队伍库（TeamsView）
- 关键词搜索框 + 6 列表格（队伍名/文件ID/赛制/来源标签/建队需求/时间），行点击进详情

### 3.4 队伍详情（TeamDetailView）
- 头部卡：队伍名 + 赛制/来源标签 + 元信息（skill 版本/模型）+ 建队需求 alert
- 主体：**6 张宝可梦卡网格**（名称中英 + 等级 / 属性徽章×1~2 / 描述列表：特性·道具·性格·太晶 / 4 个招式标签）
- 底部：折叠面板「Showdown 导出串」（等宽 pre 块）

### 3.5 对战实验室（LabView）★ 演示主线 2，信息最重
- 发起表单：A 队 vs B 队左右选择器（中间 VS 标识）+ 赛制单选（仅 BSS/OU）+ 轮数滑杆（3~50）
- 进行中/完成态：
  - 顶部**大比分板**（A 队名 + 40px 大数字 vs B 队，中间胜率/平均回合）
  - 两张 ECharts 图表卡：胜场分布（柱状）、每场回合数（折线）
  - **胜场点阵**（16px 方块序列：A 胜绿 / B 胜红 / 平灰，点击跳该场明细）
- 底部：历史会话表格
- 现状问题：比分板与图表风格平淡，对战中的紧张感/进度感不足

### 3.6 对战明细（BattleDetailView）
- 头部：场次/两队/胜负标签/总回合数
- 主体：**逐回合时间线**（el-timeline），A 队实心蓝点 / B 队空心橙点，每条「宝可梦 使用招式 → 目标」或「换上 XX」

### 3.7 分析报告列表（AnalysesView）
- 发起区：会话下拉 + 「特别关注」输入（如"重点看九尾的表现"）+ 开始按钮
- 进行中：进度日志流（同 3.2 风格）；完成态：报告标题 + 一句话结论 + 评分/用量 + 查看按钮
- 历史：报告表格（标题/评分/会话/时间，行点击进详情）

### 3.8 分析报告详情（AnalysisDetailView）★ 演示主线 3，本次升级重点
自上而下 6 个区块：
1. **报告头**：标题 + 评分徽章（S/A/B/C/D，色阶）+ 一句话结论 + 会话元信息（两队/比分/胜率/轮数）
2. **战绩解读**：一段 150~300 字文本
3. **阵容表现**：卡片网格，每只出场宝可梦一张——名称 + A队(绿)/B队(红)阵营标签 + 角色定位·出场数 + 招式使用标签（招式名×次数）+ 评语段 + 问题 alert
4. **对位分析 / 威胁识别**：左右双栏列表（攻→守 + 解读；威胁来源 + 应对）
5. **关键回合**：可点击行（场次标签 + 回合数 + 阵营 + 描述 + 箭头），跳转对战明细
6. **改进建议**：优先级标签（高/中/低色阶）+ 目标 + 改动 + 数据依据

### 3.9 设置（SettingsView）
- API 配置卡：API Key（密码框 + 已配置/未配置标签）/ Base URL / 模型名 + 保存/测试连接按钮 + 结果 alert
- 常见服务商说明卡

### 3.10 公共组件
- **TypeBadge**：18 种属性徽章，使用宝可梦官方属性色（火橙/水蓝/草绿…），是现成的品牌彩色资产
- **PokemonCard**：见 3.4

## 4. 现有视觉语言（升级基线）

- 极简风：白底 + #f5f6f8 页面底 + #ebeef2 细边框 + 8px 圆角 + 极轻阴影
- 无品牌主色（交互色是 Element 默认蓝 #409eff），logo 区纯文字
- 字阶：20px 页标题 / 16px 卡标题 / 13~14px 正文 / 12px 辅助，无强调性字重设计
- 语义色沿用 Element：成功 #67c23a / 危险 #f56c6c / 警告 #e6a23c / 信息 #909399

## 5. 设计目标

1. **数据产品的专业感** + 宝可梦主题的**克制趣味**（属性徽章色、精灵球红 #EE1515 等官方色可做点缀，不要卡通化堆砌）
2. 演示第一眼冲击力：首页改数据看板方向（统计卡 + 快速入口）、比分板、报告评分的视觉重量
3. 统一 design tokens：色板（品牌色/语义色/中性阶）、字阶、间距、圆角、阴影、hover 过渡
4. 任务进行中的「过程感」：日志流、进度、比分板的动态设计

## 6. 期望交付物

1. **Design tokens**：CSS 变量形式（可直接进 app.css），含色板/字阶/间距/阴影/圆角
2. **关键页高保真**：优先级 P0 = 首页看板、实验室（进行中态）、分析报告详情；P1 = 建队任务卡、队伍详情、设置
3. **落地说明**：每个视觉改动对应的实现方式提示（Element Plus 主题变量覆盖 / 自定义类 / 布局调整），由工程侧实现
4. 可选加分项：暗色模式 token 方案、空状态/加载态插画方向（不必出图，文字方向即可）

## 7. 边界（不要做）

- 不改信息架构、路由、后端接口；不引入构建链；不换组件库；不做移动端适配（桌面优先）
